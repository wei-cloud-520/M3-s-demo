# CLAUDE.md - 凯尔希TTS项目指令

## 开发规范

### 编码指南（Karpathy）
**先想再写。不要假设。简单优先。写完自测。**

1. **先想再写**：实现前先说明假设和方案，有不确定的先问。如果更简单的方案存在就说出来。
2. **简单优先**：只写被要求的功能，不写推测性的功能，不为单次使用的代码做抽象。200行能搞定的事不要写500行。
3. **写完自测**：写完任何非平凡的代码后，立即运行验证。不要假设它能工作。
4. **不要猜测API**：对任何库、框架、API的行为不确定时，查文档、看源码、搜issue。不要凭记忆猜。一次验证 > 十次猜测。

### 测试要求（强制）

**每完成一个模块，立即测试，确认功能正常再继续下一个。**

- 写完 `config.py` → 运行 `python -c "from config import *"` 确认能导入
- 写完 `docker_manager.py` → 运行实际docker命令验证容器状态检测、启动、停止
- 写完 `tts_engine.py` → 调用真实API合成一条短文本，确认返回音频
- 写完 `audio_processor.py` → 拼接两个测试音频文件，确认输出可播放
- 写完 `file_parser.py` → 分别解析txt/epub/pdf测试文件，确认文本正确
- 写完 `main_window.py` → 启动应用确认窗口正常显示，容器状态指示正确
- 每次修改后都要运行相关测试，不要累积多个模块后一次性测试

### 集成测试

全部模块完成后，做一次端到端集成测试：
1. 启动应用
2. 输入短文本（10字以内）→ 合成 → 播放 → 确认有声音
3. 输入长文本（200字以上）→ 合成 → 确认进度显示正常 → 播放 → 确认完整
4. 导入txt文件 → 确认文本正确显示
5. 测试另存为功能
6. 测试容器未运行时的错误处理

### 错误处理

- 遇到报错时，先读错误信息，分析根因，不要盲目修改
- 修改一个地方后，运行测试确认修改有效，再继续下一个问题
- 如果连续两次修改没解决，停下来重新分析，换思路

### UI布局规范（防遮挡/截断）

**PySide6布局铁律：**

1. **必须用布局管理器**（QVBoxLayout/QHBoxLayout/QGridLayout），禁止使用绝对定位（setGeometry/move）。绝对定位在不同分辨率和缩放下一定会出问题。
2. **文本控件必须设置 wordWrap**：QLabel、QTextEdit 等都要确保文本换行，不要让文字被截断。
3. **留足 padding 和 margin**：控件之间至少8px间距，内容不要贴边。
4. **用 sizePolicy 控制缩放**：关键控件设 QSizePolicy.Expanding，确保窗口放大时内容跟着变大。
5. **最小尺寸保障**：设置合理的 minimumWidth/minimumHeight，防止窗口缩太小后内容挤在一起。
6. **长文本实测**：UI写完后，输入一段200+字的中文测试文本，确认没有遮挡、截断、重叠。用不同长度的文本反复测。
7. **不同DPI测试**：在Windows 125%/150%缩放下检查布局是否正常。
8. **固定宽度按钮，弹性宽度输入**：按钮宽度固定，文本输入区占剩余空间。

### QSS样式规范

- 所有颜色值统一使用 hex 格式（#RRGGBB），不要混用 rgb/rgba
- 字体大小统一用 pt 或 px，不要混用
- 圆角统一用 border-radius，不要同时用 border-radius 和 border-image
- hover/pressed 状态必须有明确的视觉反馈
- 测试暗色背景下所有文字是否可读（对比度不够的换色）
