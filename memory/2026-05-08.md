## Knowledge Library 项目启动
- 博士想搭一个 Obsidian + AI 的个人知识库，由 Mon3tr 和凯尔希共同维护
- 讨论了完整的架构设计，博士理解很快，提出了很多好问题
- 项目路径：/root/knowledge-library/

### 架构决策
- 三层架构：物理存储层（Obsidian Vault）→ 知识转化层（Embedding + ChromaDB）→ 请求与输出层（AI Agent）
- 融合 PARA + Zettelkasten 方法论，按知识生命周期组织
- AI 双通道 Embedding API（GLM主/DeepSeek备），不跑本地模型（服务器内存不够）
- ChromaDB 多 collection 实现记忆隔离：knowledge_main / memory_mon3tr / memory_kaltsit / memory_shared

### 目录结构
- capture/（快速捕获）→ atlas/（永久知识卡片，原子化）
- projects/（有截止日期）/ areas/（长期关注） / references/（外部资料）
- memory/mon3tr/ / memory/kaltsit/ / memory/shared/（AI 记忆空间）

### 关键设计
- WAL 预写日志保证写入原子性和一致性
- 文件临时文件+rename 原子操作
- ChromaDB upsert 幂等
- 博士要求知识库具备数据库级可靠性（原子性、持久性、一致性）
- AI 候选链接用 [[笔记名|?]] 标注，博士确认后才生效
- memory 目录独立向量索引，按身份 token 访问对应空间
- 两种检索模式：会话启动恢复 + 对话中实时查询
